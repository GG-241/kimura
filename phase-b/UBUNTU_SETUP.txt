================================================================================
UBUNTU SETUP FOR KIMURA MOUSE HID EMPIRICAL DISCOVERY
================================================================================

This document guides you through setting up Ubuntu to communicate with the
Kimura v3.0 mouse via HID for empirical protocol discovery.

macOS restricts user-space HID writes for security reasons. Ubuntu's hidraw
interface allows full read/write access after a simple udev rule, making it
ideal for reverse-engineering.

================================================================================
QUICK START (Automated)
================================================================================

Run the bash setup script to do everything automatically:

    bash phase-b/setup_ubuntu.sh

This will:
  1. Install hidapi and Python dependencies
  2. Create the udev rule for unprivileged access
  3. Reload udev and trigger device re-enumeration
  4. Verify the mouse is visible

Then test with:

    python3 phase-b/empirical_probe.py list
    python3 phase-b/empirical_probe.py send "04 01"

Watch the LED. If it changes, you have working write access.

================================================================================
MANUAL STEPS (if you prefer)
================================================================================

1. Update package list:
   $ sudo apt-get update

2. Install hidapi and development libraries:
   $ sudo apt-get install -y libhidapi-libusb0 libhidapi-dev python3-pip

3. Install Python hidapi:

   Option A (Recommended): Via system package
   $ sudo apt-get install -y python3-hidapi

   Option B (if package unavailable): Via pip with --break-system-packages
   $ pip3 install --break-system-packages hidapi

   Option C (best practice): Create a virtual environment
   $ python3 -m venv ~/.venv-kimura
   $ source ~/.venv-kimura/bin/activate
   $ pip3 install hidapi
   $ # Then run empirical_probe.py from within the venv

4. Create udev rule for unprivileged HID access:
   $ sudo tee /etc/udev/rules.d/70-kimura.rules > /dev/null <<'EOF'
   SUBSYSTEM=="hidraw", ATTRS{idVendor}=="248a", ATTRS{idProduct}=="5b49", MODE="0660", TAG+="uaccess"
   SUBSYSTEM=="hidraw", ATTRS{idVendor}=="248a", ATTRS{idProduct}=="5b4a", MODE="0660", TAG+="uaccess"
   EOF

5. Reload and trigger udev:
   $ sudo udevadm control --reload
   $ sudo udevadm trigger

6. Plug in the mouse (if not already connected)

7. Verify it appears:
   $ lsusb | grep -i 248a
   Expected output: Bus XXX Device YYY: ID 248a:5b49 Telink Semiconductor Corp. Wireless Receiver

8. Test HID communication:
   $ python3 phase-b/empirical_probe.py list
   Should show the device without permission errors.

9. Test write access:
   $ python3 phase-b/empirical_probe.py send "04 01"
   Watch the LED — if it changes, writes are working!

================================================================================
TROUBLESHOOTING
================================================================================

Q: "lsusb" doesn't show the device
A: Plug the mouse in directly to the Ubuntu machine (not through a dock/hub)
   Check that it's using the cable that came with it (or a known data cable)

Q: "empirical_probe.py list" shows "No compatible device found"
A: Run:  $ ls -la /dev/hidraw*
   If no hidraw* files exist, the udev rule didn't apply.
   Reconnect the mouse and check:  $ dmesg | tail -20

Q: "empirical_probe.py send" gives permission error
A: Run:  $ id -G | grep -q 999 && echo "In input group" || echo "NOT in input group"
   If not in group 999, add yourself:
   $ sudo usermod -a -G input $USER
   Then log out and back in.

Q: "pip3 install hidapi" fails with "externally managed environment"
A: This is Python 3.11+ protection. Use one of these:
   1. sudo apt-get install -y python3-hidapi  (recommended)
   2. pip3 install --break-system-packages hidapi  (quick, safe on single-purpose machine)
   3. python3 -m venv ~/.venv-kimura && source ~/.venv-kimura/bin/activate && pip3 install hidapi
   The updated setup_ubuntu.sh script handles this automatically.

Q: "send" command doesn't change the LED
A: Try with different opcodes (the protocol is still unknown)
   See phase-b/EMPIRICAL_DISCOVERY.md for exploration strategy

================================================================================
NEXT STEPS
================================================================================

Once writes are working, use empirical_probe.py to explore the protocol:

  # Try LED control commands
  $ python3 phase-b/empirical_probe.py led

  # Try DPI control commands
  $ python3 phase-b/empirical_probe.py dpi

  # Send custom hex commands
  $ python3 phase-b/empirical_probe.py send "02 FF 00 00"
  $ python3 phase-b/empirical_probe.py send "04 02"

Document your findings in phase-b/EMPIRICAL_DISCOVERY.md as you discover
what each opcode does.
